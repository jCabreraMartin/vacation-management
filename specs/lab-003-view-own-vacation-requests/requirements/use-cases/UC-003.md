## Alcance

Consulta por un empleado de la lista y el detalle de sus solicitudes, incluido el estado actual.

## Nivel

Objetivo de usuario.

## Actor principal

Empleado (actor hipotético del laboratorio).

## Partes interesadas e intereses

- Empleado: consultar sus propias solicitudes y conocer su estado.
- Organización: limitar la visibilidad según SEC-001 (LAB-HYP).

## Precondiciones

- El empleado inicia la consulta de sus solicitudes.
- El contexto que permite identificar al empleado debe estar disponible para aplicar SEC-001; el
  mecanismo de autenticación no está definido.

## Garantía de éxito (postcondiciones)

- Se muestra la lista y el detalle de las solicitudes propias disponibles.
- El estado actual de cada solicitud consultada es visible.

## Garantía mínima

- El empleado no obtiene acceso a solicitudes de otra persona a través de esta consulta.

## Disparador

El empleado solicita consultar sus propias solicitudes.

## Escenario principal de éxito

| Paso | Actor | Sistema |
| --- | --- | --- |
| 1 | Solicita ver sus solicitudes. | Recibe la petición asociada al contexto del actor. |
| 2 | — | Limita la consulta a solicitudes propias (SEC-001). |
| 3 | — | Devuelve la lista con los estados actuales. |
| 4 | Selecciona una solicitud de la lista. | Presenta el detalle de esa solicitud y su estado. |

## Pasos detallados

1. **Empleado** inicia la consulta.
2. **Sistema** aplica el límite de propiedad definido de forma hipotética en SEC-001.
3. **Sistema** recupera los datos de las solicitudes propias y sus estados.
4. **Empleado** puede seleccionar una solicitud para consultar su detalle.

## Extensiones (flujos alternativos)

- **2a. Se intenta consultar una solicitud ajena:** el acceso se deniega (SEC-001). El código de
  respuesta o presentación del error no está especificado.
- **3a. No hay solicitudes propias:** el comportamiento de estado vacío no está definido.
- **3b. No se puede completar la consulta:** timeout, reintentos y mensaje de error no están definidos.

## Requisitos especiales

- No hay NFR aprobados para tiempo de respuesta, disponibilidad, accesibilidad ni retención.
- El método de autenticación y el modelo de autorización real permanecen sin definir.

## Variaciones tecnológicas y de datos

Flujo lógico fullstack: interfaz de consulta → lógica de aplicación que aplica SEC-001 → lectura del
almacén de datos no especificado. No se asume endpoint, consulta, tecnología ni modelo de datos.
